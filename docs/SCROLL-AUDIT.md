# 1.3.0 스크롤 결함 조사

사용자가 보고한 “맨 위 전에 멈춤”과 “약간의 버벅임”을 기준으로 기존 1.2.0 APK부터 검사했습니다. 연결 가능한 환경은 전용 Android 15·16 에뮬레이터이며, 사용자의 실제 갤럭시와 문제가 발생한 앱 이름은 제공되지 않았습니다. 따라서 이 문서는 제품 코드와 아래 재현 범위의 조사 기록이지, 모든 Android 앱을 실행한 전수검사 인증이 아닙니다.

## 추가 수정과 회귀 검사

- 진행 중 같은 화면의 목록 객체가 재생성되면 제한적으로 재연결합니다. 같은 앱·창에서 식별 정보와 영역이 맞는 후보가 하나일 때만 진행하며, 이전 객체의 위치 증거를 폐기합니다.
- 새로 읽은 동작 목록에서 위쪽 이동이 사라졌을 때, 오래된 양수 위치 때문에 맨 위를 추가로 당기지 않도록 수정했습니다. 검사에서는 실제 첫 행 도달 이후의 추가 터치도 확인합니다.
- 매 단계의 전체 트리 탐색을 대상 노드 갱신으로 바꿨습니다. 네이티브 애니메이션은 제한된 자식 좌표도 확인해, 드문 접근성 알림 사이에서 아직 움직이는 애니메이션을 스와이프로 끊지 않도록 했습니다.
- 일부 이동을 마친 네이티브 요청 뒤의 고정 대기를 줄였습니다. 수정 도중 측정한 약 468ms의 정지 구간은 약 100~117ms로 줄었습니다. 최종 두 OS의 수치는 검증 기록에 별도로 남깁니다.
- 스크롤 대기 중 노드 갱신 예외도 처리합니다. 전체 화면에서 처음 터치 창을 만들 때부터 상태바가 숨겨져 있으면 터치를 통과시킵니다.
- 움직이지 않는 화면의 반복 스와이프 제한, 이미 맨 위인 알림 없는 화면, 앱 전환·재탭 취소·권한 해제·실제 최근 앱 모두 닫기를 다시 검사합니다.

최종 제품 APK의 전체 실행 결과, 위치·렌더링 수치, 서명과 빌드 결과는 [VERIFICATION.md](VERIFICATION.md)에 있습니다.

## 성능 판정의 구분

일반적으로 이어지는 목록은 기록된 위치 샘플 사이 100ms 이하를 검사합니다. 부분 이동 후 다음 방식으로 넘기는 사례는 150ms 이하, 목록 객체 자체가 파괴·재생성되는 사례는 재연결 정지 600ms 이하를 별도로 검사합니다. 이 두 조건을 “중단 없는 60fps 스크롤”로 표현하지 않습니다. 화면 재생성은 대상 앱의 애니메이션도 종료시킵니다.

위치 콜백 간격 외에 Android `gfxinfo framestats`의 유지된 프레임 기록에서 P95/최대 완료 시간과 프레임 마감 초과도 수집합니다. 버퍼에 남은 표본이며, 화면 표시까지 포함한 전체 구간의 완벽한 프레임 성능을 뜻하지 않습니다. 에뮬레이터 수치를 삼성 디스플레이의 FPS 보장으로 바꾸어 해석하지 않습니다.

## 검사 자체의 보강

Android 15에서는 기존 약 16,000px 웹 준비 구간을 개선된 엔진이 4초 전에 끝냈습니다. 시간 제한을 검증할 수 있도록 실제 터치로 50,000px 이상 아래까지 이동한 뒤 검사하도록 바꿨습니다. 약 85,000px에서 중간 중단과 다음 탭 재개를 확인했으며, 제품 코드의 실패로 분류하지 않았습니다.

## 검토와 남은 범위

`code-review` 스킬의 별도 code-reviewer와 architect를 요청했지만 둘 다 설정된 `gpt-5.5` 모델 접근에서 404 오류로 종료됐습니다. **독립 검토 불가(independent review unavailable)**이며, 작성자의 코드 확인과 실행 검증을 독립 검토 승인으로 대체하지 않았습니다. 이 작업에 독립적인 APPROVE/merge-ready 판정은 없습니다.

삼성 실기기, 실제 문제 앱·앱 버전, 삼성 갤러리·인터넷, RecyclerView·Compose·역순 채팅 화면, 모든 접근성 제공 방식, 제조사 절전·장시간 대기는 추가 검증 대상입니다. 앱의 접근성 지원과 자체 애니메이션을 공통 API로 모두 동일하게 강제할 수는 없습니다. 10,000항목 검사는 시간 제한 20초를 사용했고 기본값 12초나 임의 길이의 화면에서 한 번에 끝남을 증명하지 않습니다. 기본/최대 시간 제한과 미검증 항목은 앱 안내 및 [실기기 확인표](QA-CHECKLIST.md)에 남깁니다.
