## 실제 상단 도달과 움직임

제품과 별도 프로세스인 `kr.toptap.fixture`를 실제로 스크롤한 뒤 상태바에 한 번 탭을 주입했습니다. 목록은 첫 항목뿐 아니라 첫 행의 잘림도 0인지 검사합니다. 도달 직후 다시 움직이지 않는지 기다려 재확인합니다.

표의 각 값은 **기록된 이동 시간 / 최대 위치 샘플 간격 / 앱이 보낸 스와이프 수**입니다. 시작 준비와 ADB 통신에 걸린 전체 테스트 시간과 구분합니다.

| 화면 | Android 15 | Android 16 |
| --- | --- | --- |
| 기본 목록, 120번째 항목 | 2.000초 / 18ms / 0회 | 2.000초 / 19ms / 0회 |
| 사진 형태 격자, 120번째 항목 | 0.666초 / 19ms / 0회 | 0.666초 / 19ms / 0회 |
| 맨 위 동작 없는 목록, 120번째 항목 | 0.866초 / 25ms / 2회 | 0.866초 / 19ms / 2회 |
| 맨 위 동작 없는 깊은 목록, 350번째 항목 | 1.783초 / 19ms / 4회 | 1.800초 / 19ms / 4회 |

움직임이 있는 경우 5개 이상의 위치 샘플, 100ms 이상의 이동, 실제 맨 위 도달, 도달 전 역방향 이동 없음, 샘플 사이 100ms를 넘는 정지 없음으로 판정합니다. 물리 스와이프를 사용했다면 손을 뗀 뒤에도 200px 이상 이동하는 관성을 별도로 확인합니다. 원시 좌표는 `motion-emulator-5580-*.json`, `motion-emulator-5582-*.json`에 있습니다. 이는 삼성 디스플레이의 실제 렌더링 FPS 보장이 아닙니다.

[실제 화면 녹화](media/toptap-1.2-scroll-demo.mp4)는 Android 16에서 별도로 촬영했습니다. 350번째 항목에서 한 번 탭 후 실제 첫 행까지 이동하며, 처음·이동 중·도착 화면을 추출해 확인했습니다. 위 성능 표는 녹화 부하 없이 측정한 전체 검사 결과입니다.

실제 Chrome에서는 이 PC의 로컬 서버가 제공하는 300개 구간의 문서를 열고 내려간 뒤, 한 번 탭 후 DOM의 `scrollY=0`을 확인했습니다.

- API 35: 0.436초, `instant_native`, 최종 `scrollY=0`
- API 36: 0.318초, `instant_native`, 최종 `scrollY=0`

검사한 Chrome 문서와 WebView는 문서 시작을 드러내는 네이티브 요청을 **즉시 이동**으로 처리했습니다. 이를 부드러운 애니메이션 통과로 분류하지 않습니다. [Chrome API 35 좌표](chrome-motion-api35.json)와 [API 36 좌표](chrome-motion-api36.json)에 구분해서 기록했습니다.

## 원터치·투명 영역·최근 앱 모두 닫기

- 시스템이 보고한 상태바 높이 전체에서 가로 5 × 세로 3, 총 15개 위치를 검사했습니다. 옛 두 번 터치·좁은 영역·표시선 설정이 남아 있어도 한 번 탭으로 동작합니다. 가로 방향에서도 왼쪽·중앙·오른쪽을 확인했습니다.
- 기본·밝은 배경/어두운 아이콘·어두운 배경/밝은 아이콘 모드에서 기능 끔, 대기, 스크롤 중 상태바 전체를 원시 RGBA로 비교했습니다. 비교 범위는 API 35: 높이 128px, 552,960바이트, API 36: 높이 128px, 552,960바이트이며 변경 바이트는 0입니다. 시스템 시계가 분 경계를 넘지 않도록 검사 시간을 조절했고 화면을 보정하거나 마스킹하지 않았습니다. 실행 유지 알림 권한은 거부 상태입니다.
- 실제 최근 앱 화면의 **Clear all 버튼**을 눌러 제품과 fixture 화면이 모두 제거된 것을 확인한 뒤, 탑탭 화면을 열지 않고 fixture에서 다시 상단 이동했습니다. 각 OS에서 3회 반복했고, 실제 포그라운드 서비스 상태도 확인했습니다. 회전 기록에 남는 과거 화면 문자열은 실행 중 화면으로 세지 않습니다.
- 프로세스 강제 제거 후 새 PID의 접근성 연결과 스크롤 복구도 확인했습니다. 이 검사는 사용자가 누르는 시스템의 명시적인 **중지**와 다릅니다. 별도 중지 검사에서는 전체 앱 프로세스·서비스·터치 영역이 실제로 종료되는 것을 확인했습니다.

## 나머지 실행 범위

49개 시나리오에는 기본/중첩 목록, 격자, WebView, 실제 Chrome, 첫 행 직접 이동, 무한 스크롤 양 인자, 페이지 위쪽 이동만 제공하는 화면, 가로 전용 목록·범위 위젯 보호, 선택적인 호환 스와이프, 시간 제한/재개, 앱 제외/일시정지, 알림창 드래그, 재탭 취소, 다른 창으로 이동, 잠금/해제, 접근성 해제, 이미 맨 위일 때 당김 방지, 이전 설정 마이그레이션, 동의 없는 활성화 방지, 회전, 전체 화면 터치 통과/복구, 빠른 설정 타일의 중지/재개를 포함합니다.

## UI와 배포 파일

홈·설정·빠른 모드 토글·도움말, 글자 크기 2배의 홈/설정, 가로 설정/도움말, 접근성 설명 대화상자를 캡처했습니다. 실제 버튼으로 화면을 이동하고 빠른 모드 설정 저장을 확인했습니다. 설명 대화상자를 취소해도 동의가 생기지 않는 것을 검사합니다. 큰 글자와 가로 화면의 긴 내용은 스크롤할 수 있습니다.

[홈](screenshots/home.png) · [설정](screenshots/settings.png) · [큰 글자](screenshots/settings-large-text.png) · [가로 화면](screenshots/settings-landscape.png) · [동의 설명](screenshots/disclosure.png)

JDK 21, AGP 9.2.1, Gradle 9.4.1, compile/target SDK 36, min SDK 26으로 빌드했습니다. 제품 lint의 남은 경고 3개는 `OldTargetApi`, `AndroidGradlePluginVersion`, `GradleDependency`입니다. 검증한 SDK/도구 버전을 고정했습니다. 테스트 fixture의 경고 13개는 테스트 초기화, 진단 문자열, 백업/아이콘 설정 등에 해당하며 오류는 없습니다. Gradle은 향후 10.x 관련 deprecated API 안내를 출력합니다.

`debugRuntimeClasspath`에 외부 의존성은 없습니다. 인터넷·사진·연락처 등의 권한은 없으며, manifest에 포그라운드 실행·specialUse·알림 권한을 선언합니다. 접근성/타일 바인딩은 각각 시스템 권한으로 보호합니다. APK v2 서명 검증과 1.1.0과 동일 인증서 사용을 확인했습니다. 현재 APK는 디버그 서명이며, 배포 키와 스토어 심사를 완료한 출시 빌드는 아닙니다.

## 재현

```sh
sh scripts/build.sh
python3 scripts/e2e.py --serial emulator-5580 --adb /your/android/sdk/platform-tools/adb
python3 scripts/e2e.py --serial emulator-5582 --adb /your/android/sdk/platform-tools/adb
python3 scripts/capture-ui.py --serial emulator-5582 --adb /your/android/sdk/platform-tools/adb
```

1080×2400 ARM64 전용 에뮬레이터를 한 대씩 사용했습니다. 스크립트는 개인 기기를 거부하고 지정한 에뮬레이터의 테스트 설정만 바꿉니다. 접근성 서비스 목록은 종료 시 복원합니다. Chrome의 계정 없는 최초 실행은 미리 완료해야 합니다. Clear all 위치는 해당 AVD의 Pixel Launcher 기준입니다. 테스트 앱·로컬 웹 서버·합성 좌표 기록은 배포 APK에 포함되지 않습니다.

## 남은 검증과 한계

**삼성 실기기와 One UI, 실제 삼성 갤러리·삼성 인터넷 및 사용자가 문제를 겪은 앱 화면, 밤새 대기·절전·재부팅·메모리 압박, 폴더블·다중 디스플레이·TalkBack 동시 사용은 검증하지 못했습니다.** Android 8~14는 정적 API 검사 범위이며 실행 검증은 하지 않았습니다. 알림 허용 상태에서의 기기별 알림 표현과 시스템 중지 UI도 추가 확인 대상입니다. [실기기 확인표](QA-CHECKLIST.md)에 남겼습니다.

모든 앱이 접근성 이동을 지원하지는 않으며 대상 앱의 애니메이션 곡선을 탑탭이 강제할 수 없습니다. 아주 긴 화면은 기본 12초, 최대 20초 제한에 도달하면 다음 탭이 필요할 수 있습니다. 모든 앱에서 아이폰과 완전히 동일한 동작이나 제조사 정책을 무시한 영구 실행, 모든 경우의 상용 검증 완료를 주장하지 않습니다.
